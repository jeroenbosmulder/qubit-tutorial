# room/ — live-session layer (slices 1–3)

Turns the tutorial into the participant page and the deck into the room's big screen.
Spec: `next/docs/spec-and-reuse-audit.md` §1–3. Storyboard: `next/docs/storyboard-coins-to-qubit.md` v0.3.

## Files

| file | role |
|---|---|
| `relay-config.js` | Supabase URL + anon key (from your earlier QR setup). Empty = local mode. |
| `relay-transport.js` | One message bus shaped like a `BroadcastChannel`: same-browser leg always, Supabase Realtime broadcast leg when configured. Dedupes, coalesces nothing itself. |
| `room.js` | Protocol: roster (20 designed seats), presenter store (assigns seats, publishes state, reduces phone snapshots, persists across reload), participant store (joins, sends snapshots, re-sends on reconnect), React hooks `Room.usePresenter()` / `Room.useParticipant()`. |
| `fake-phones.html` | N simulated phones for testing the deck without devices. |
| `test/*.test.js` | Node tests: protocol on an in-memory bus; tutorial room mode and presenter figures rendered in jsdom. |

Consumers: `presentation/room-figures.jsx` (one `Fig…Room` per scene, 15 so far), `presentation/room-slice1.dc.html` (presenter harness: scenes 0–13, 17 slides), `next/build-your-own-qubit.jsx` (room mode; `next/index.html` regenerated by `next/build-index.py`).

## Run it

1. Fill `relay-config.js` (or leave empty for a one-browser test).
2. Serve the repo over http (GitHub Pages, or `python3 -m http.server` at the repo root) — `.dc.html` decks fetch their modules, so `file://` won't do.
3. Open `presentation/room-slice1.dc.html`. It picks a session code and puts it in the URL. Slide 1 shows the QR and the code; **P** opens the projector mirror, **N** the notes.
4. Phones scan the QR → `next/index.html?session=CODE` → pick an emoji → join. Each phone appears on slide 1 with its seat number.
5. Arrow to slide 2 (scene 1, round A) — phones show the Flip button; every tap lands on the pooled line. Slide 3 is round B (secret coins). The figure's buttons also switch rounds and reset a round.
6. Slides 4–8 are scenes 2–6: per-phone bars; the half-plane (buttons: add the second number, pool each round, reveal the true coins — phones follow each); the Bernoulli circle and the pointer/needle, both driven by the presenter's slider (phones follow it, or drag their own and snap back); the two doubts.
7. Slides 9–17 are scenes 7–13 (light). Phones get a beam with a secret angle from their seat; they send photons per sheet angle. Presenter buttons: lens angle (7), reveal angles (9), spotlight (10), ask 0°/45°/90°/135° (11), middle sheet in/out (11), twin pair + 0°/45° view (13). Changing a phone's noise knob starts a new beam (its counts clear).

No devices at hand: open `room/fake-phones.html?session=CODE` in another tab of the same browser (local mode works without Supabase).

Standalone tutorial is unchanged: `next/index.html` without `?session=` behaves as before.

## Wire protocol

Event `pf` on topic `<TOPIC_PREFIX>-<SESSION>`; every message gets `from` and `_id` from the transport.

```
presenter → all     { type:'state', patch:{ scene, round, p, showBandAxis, showPooled, revealCoins, resetToken,
                                            lens2, question, reveal, spotlight, mid, midIn, fullDisk, pair, …,
                                            roster:{[from]:{slot,tag}}, agg:{ tally:{A:[…],B:[…]}, beam:[{slot,tag,noise,q}] } } }
phone → presenter   { type:'up', name:'hello',        data:{ tag } }
phone → presenter   { type:'up', name:'sync-request', data:{} }
phone → presenter   { type:'up', name:'tally',        data:{ A:{n,heads}, B:{n,heads} } }   ← a SNAPSHOT, last write wins
phone → presenter   { type:'up', name:'beam',         data:{ noise, q:{ "0":{n,passed}, "45":{n,passed}, … } } }   ← Part II, one tally per sheet angle
```

`agg` is the presenter's throttled (300 ms) summary of the room, so every phone can draw the others faded around its own dot.

Secrets never travel: both sides compute `Room.secrets(slot)` from the seat number (`room.js` → `SLOTS`, spec §3.2).

Slides drive state: `<section data-scene="1" data-pf-round="B">` publishes `{scene:1, round:'B'}` on `slidechange`.

## Adding a scene (the pattern for slices 2–4)

- Presenter: a figure in `room-figures.jsx` that calls `Room.usePresenter()` and reads `phones[*].up.<name>`; buttons call `publish({...})`. Put it on a slide with `data-scene="N"`.
- Phone: a `RoomStepN({ room })` component in the tutorial; read `room.state` and `room.me`; send one snapshot per change with `room.send(name, data)` from a `useEffect` (never during render). Register it in `ROOM_STEPS`.
- Aggregations that several figures need go into `room.js` next to `tallies()`.

## Cache busting

GitHub Pages caches files for ~10 minutes and browsers keep fetched modules. After changing `room-figures.jsx`, bump the `?v=` on its `<x-import from="./room-figures.jsx?v=N">` lines in the deck (and hard-reload once); the same trick works for the `../room/*.js` script tags in `next/index.html` if a phone shows stale behaviour.

## Known limits / next

- The projector mirror across devices (presenter-kit's figure sync over Supabase) is not wired yet; the local mirror (**P**) works as before. The hook point is one line in `presenter-kit.js` and `fifteen-figures.jsx`: accept an injected transport instead of `new BroadcastChannel(...)`.
- Seats are assigned in join order; there is no UI yet to reassign a seat.
- Round tallies on a phone live in `sessionStorage`; closing the tab loses them (the presenter keeps its copy).
